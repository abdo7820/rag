Architecture

Two pipelines, chained together

A retrieval pipeline finds the evidence. A 6-step generation chain decides — deterministically, where possible — whether and how to answer with it.

Candidate pool
30 per retriever
RRF constant
k = 60
Kept after fusion
8 candidates
Final results
top 5
Graph facts limit
15 per question
01
Guardraildeterministic
Regex screen blocks personal medical-advice questions (dosage, prescriptions, diagnosis) before any model is called.
02
Query rewriteLLM
Expands abbreviations and adds medical synonyms to the search query, improving retrieval recall. Falls back to the original question on failure.
03
Retrievehybrid + graph
Vector + BM25 → RRF → rerank on the rewritten query, plus a Neo4j graph lookup on the ORIGINAL wording so entity names still match verbatim.
04
Scope checkLLM + confidence signal
An LLM topical judgement is combined with the retrieval confidence score — both must agree the question is off-topic before it's rejected, so one bad call can't wrongly block an answer.
05
Draft answerLLM
Answers strictly from retrieved evidence with inline citations. Retries on transient failures; never silently returns an unfinished draft.
06
Verify & finalizeLLM + deterministic
Re-checks every claim and citation against the real evidence; fabricated citations get the answer rejected outright rather than shown. A confidence flag and disclaimer are appended last.

API endpoints

Everything this console calls is plain HTTP — same routes work from Postman, curl, or your own frontend.

GET/health
Confirms the server is up and shows whether Groq / Neo4j / vector DB / BM25 index are configured.
→ 200 { status, groq_configured, neo4j_configured, vector_db_found, bm25_index_found }
POST/search
Runs hybrid retrieval only — semantic + BM25 → RRF, optionally reranked. No LLM call.
{ "query": "What causes liver cirrhosis?", "top_k": 5, "rerank": true }
POST/ask
Runs the full 6-step chain and returns a cited, verified answer. Requires GROQ_API_KEY on the server.
{ "question": "What causes liver cirrhosis?", "top_k": 5 }
GET/graph/{entity_name}
Looks up an entity in the Neo4j knowledge graph and returns its relationships with section/page provenance.
→ 200 { entity, facts: [{ source, relation, target, section, page }] }
